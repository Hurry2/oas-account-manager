# OAS 账号列表管理工具

给 [OnmyojiAutoScript](https://github.com/runhey/OnmyojiAutoScript)（OAS）的「多账号切换执行任务」
类功能用的离线账号表编辑器（协战 / 切号 / 勾协小号）。

**独立程序**：不改 OAS 代码，只读写你指定的 `config/{配置}.json`。
可以放在任何位置，指向任意 OAS 目录（本地或局域网共享都行）。

---

## 快速开始

### 1. 需要什么

- **Python 3.8+**（任选一种：系统已装 / 放一份便携版到工具目录的 `python\` / 用 OAS 自带的 `toolkit\`）
- **Chrome 或 Edge**（独立窗口模式用它们的 `--app`）

### 2. 告诉它 OAS 在哪

三选一（优先级从高到低）：

```powershell
# 方式 A：命令行参数
python server.py --root "D:\你的OAS目录"

# 方式 B：环境变量（设一次，以后双击快捷方式也生效）
setx OAS_ROOT "D:\你的OAS目录"

# 方式 C：先直接启动，再在页面右上角「切换目标」里填路径（会记住）
```

目标目录下必须有 `config` 子目录，例如 `D:\OAS\config\模板.json`。

### 3. 启动

| 方式 | 命令 |
| --- | --- |
| **独立应用窗口**（推荐，无地址栏） | 双击 `启动账号管理（独立窗口）.vbs` |
| 普通浏览器标签页 | 双击 `启动账号管理.vbs` |
| 带控制台（看日志） | 双击 `启动账号管理.bat` |
| 命令行 | `python server.py --app` |

默认端口 **22299**，已在运行时会复用并直接开页面。

创建桌面快捷方式：右键 `install-shortcut.ps1` → 使用 PowerShell 运行。

### 4. 退出

页面右下角「退出工具」，或双击 `关闭账号管理.bat`。

## 为什么需要它

OAS 把多账号列表存成一批平铺的 key：

```json
{
  "assist_battle": {
    "assist_battle_config": { "account_count": 3 },
    "account_list_1": { "character": "…", "svr": "…", "account": "…", … },
    "account_list_2": { … },
    "account_list_3": { … }
  }
}
```

- **顺序 = key 编号顺序**，没有独立的排序字段
- `account_count` 只用来"补空卡"，**调小它不会删掉多余的 key**（实测：count 6→3，落盘仍是 6 个 key）
- 面板只能"把数量 +1 再在末尾填一张空卡"，所以**中间插队、删除、排序都做不到**

本工具的做法是**整表重写**：把整个列表读出来 → 在内存里随心增删排序 → 一次性按新顺序重写 `account_list_1..N` 并同步 `account_count`。这样既不会留下空洞，也不会漏改计数。

支持的列表：

| 目标任务 | 列表 key | 计数字段 |
| --- | --- | --- |
| `assist_battle`（一键协战） | `account_list_N` | `assist_battle_config.account_count` |
| `account_switch`（切号执行任务） | `account_list_N` | `account_switch_config.switch_account_count` |
| `find_jade`（寻勾协小号） | `sup_account_list_N` | `find_jade_config.sup_account_count` |

### 切号执行任务（account_switch）的特别说明

这个任务除了账号列表，还有一个 **`current_index` 轮换指针**——记录"下一个该切哪个号"，
由脚本自己维护，表示账号列表里的**下标**（0 开始）。

工具里删账号或拖动重排之后，指针可能指错人（比如删掉第 1 个，指针还是 1，
就白白跳过了一个号）。所以：

- 界面上会用一条信息栏显示 **下次切到第几个号、是哪个角色**
- 保存时后端会检查指针：**越界（`>= 列表长度`）自动归零**
- 指针在范围内时**不动它**——重排后指针位置的含义变了，但脚本有自己的进度语义，
  工具不该擅自"修正"到别的号

另外 `trigger_all_enabled_tasks`（切完号是否触发所有已启用任务）也会显示出来，
方便确认当前配置。这个字段工具**只读不改**，要改请去 OAS 界面。

## 放在哪里 / 怎么找到 OAS

### 工具本身放哪都行

```
<任意目录>\oas-account-manager\     ← 工具放这里（和 OAS 是否同盘无关）
├─ server.py
├─ ui.html / app.js / core.js / ui.css
└─ python\                          ← 可选：便携 Python 放这里
```

`server.py` 的静态资源、`backups/`、`.runtime.json`、`window.json` 都按
**脚本自身所在目录**定位，不依赖工作目录，所以在哪个目录执行都能跑。

### 它怎么找 OAS

工具会按顺序找两样东西：

| 要找的 | 查找顺序 |
| --- | --- |
| **OAS 根目录** | ① `--root` 参数 → ② `OAS_ROOT` 环境变量 → ③ `settings.json` 里的默认预设 → ④ 从工具目录向上找含 `config/` 的目录 → ⑤ 从当前目录向上找 |
| **Python 解释器** | ① `ACCOUNT_MANAGER_PYTHON(W)` 环境变量 → ② 工具目录下的 `python\` → ③ 工具目录下的 `toolkit\` → ④ 向上找 `toolkit\` → ⑤ PATH 上的 `python` |

找不到 OAS 根时不会瞎猜，会直接告诉你三种指定方式。

### 指定 OAS 根的三种方式

```powershell
# 方式 A：命令行（临时）
python server.py --root "E:\git_src\OnmyojiAutoScript"

# 方式 B：环境变量（一次性，之后双击启动器也生效）
setx OAS_ROOT "E:\git_src\OnmyojiAutoScript"

# 方式 C：页面右上角「切换目标」里填路径（会写进 settings.json 记住）
```

`--root` 也可以直接指到 `config` 目录本身，会自动取它的上一级。

### 便携部署（拷给别人用）

想让对方**不装 Python** 也能跑：

1. 把工具整个目录拷过去
2. 在目录下建 `python\`，放一份 Python 的嵌入式版（`python.exe` + `pythonw.exe` + `Lib`）
3. 双击 `启动账号管理（独立窗口）.vbs` 即可

### 管理**另一台电脑**上的 OAS（局域网）

OAS 跑在局域网另一台机器上时，把共享目录注册成预设即可在本机操控：

```
\\oas\OnmyojiAutoScript-easy-install
```

两种方式：

**A. 页面里点「切换目标」** —— 填路径（可起名，如「局域网 OAS」）→ 「切换到这个路径」。
列表里会标出 `局域网` / `可访问`，切换立即生效，并自动记住为默认。

**B. 启动参数**：

```powershell
python -B server.py --root "\\oas\OnmyojiAutoScript-easy-install"
```

已实测可用的操作：读配置列表（那台机器上的 12 个配置）、读账号卡、**保存写回**（56 张卡整表重写）、
备份落到本机 `backups/`、导出 JSON。保存后用 OAS 的 `AssistBattle` 模型读回验证，56 张全部有效。

预设保存在工具目录的 `settings.json`，重启后仍然生效：

```json
{
  "default": "lan",
  "roots": [
    { "name": "local", "path": "E:\\git_src\\OnmyojiAutoScript" },
    { "name": "lan",   "path": "\\\\oas\\OnmyojiAutoScript-easy-install" }
  ]
}
```

**必须遵守（比本地模式更重要）**：

1. **保存前先停掉那台机器上的 OAS 实例**。OAS 进程持有内存配置，任何一次
   `save()` 都会把内存里的旧账号表整体写回，覆盖你刚保存的内容——
   而且这个过程**没有任何提示**。正确流程：那边停实例 → 你这边改 → 那边再启动。
2. 页面顶部会显示红色的「局域网」警告条，看到它就要想起第 1 条。
3. 网络断开时保存会失败，但**不会留半截文件**（原子写入）；重试即可。
4. 备份落在**你本机**的 `backups/`，那台机器不会有备份。
5. 如果 `\\oas` 主机名解析不了，可以换成 IP：`\\192.168.x.x\OnmyojiAutoScript-easy-install`。

### 移动时要注意的 6 点

1. **桌面快捷方式是绝对路径**，移动后旧快捷方式会失效。移动完**重新运行一次** `install-shortcut.ps1`（会覆盖旧的）。
2. **不要只移动一部分文件**。至少要带上：`server.py`、`ui.html`、`ui.css`、`app.js`、`core.js`、`_find_python.bat` 和三个启动 bat/vbs。只缺任何一个都可能起不来（`check-dom.js` 能查出来）。
3. **`.runtime.json` 会在移动后失效**（里面记的是旧 PID 和旧路径）。如果移动前工具还在跑，先在原位置退出，或移动后执行一次 `--stop` 清掉。
4. **`backups/` 跟着工具目录走**。移动工具等于换了一套备份历史；想保留就往新位置一起复制。
5. **快捷方式里的工作目录**是工具目录。如果你手工改过 `.lnk` 的「起始位置」，移动后要一并改。
6. **端口不变**（默认 22299）。同时只跑一份工具；重复启动会复用已有实例，不会冲突。

> 这些约束已经写成自动检查 `node check-portable.js`，改代码或挪文件后跑一次就知道有没有破坏可移植性。

## 启动

### 方式一：独立窗口（推荐，像桌面应用）

双击 **`启动账号管理（独立窗口）.vbs`**（或 `.bat`）：

- 不弹黑色控制台窗口
- 页面用 **Chrome / Edge 的 `--app` 模式**打开 —— **没有地址栏、没有标签栏**，
  看起来就是一个独立的桌面程序，任务栏里也是单独的一项
- 窗口尺寸默认 1280×860，可用 `--app-size 1400,900` 调整
- **窗口位置和大小会自动记住**：拖到你喜欢的位置后，下次启动还在那儿（见下）
- 用的是独立的浏览器配置目录 `.app-window/`（在工具目录里），
  不会和你日常用的浏览器抢实例、也不影响你的书签/登录状态

找不到 Chrome / Edge 时**自动退回系统默认浏览器**（普通标签页），不会报错。

#### 窗口位置 / 大小记忆

独立窗口模式下，工具会记住你上次把窗口拖到哪儿、拉多大：

- 页面把自己量到的 `outerWidth/outerHeight` + `screenX/screenY` 上报给后端
  （拖动/缩放时防抖保存，2 秒轮询兜底，关页面前再补一次）
- 后端存到工具目录的 `window.json`
- 下次启动时用 `--window-size` / `--window-position` 传回去，窗口出现在原位

校验规则（防止窗口缩成一条线或跑到屏幕外）：

| 规则 | 说明 |
| --- | --- |
| 最小 640×480 | 更小的值直接拒绝（最小化时页面会量到很小的数） |
| 位置范围 ±32000 | 允许负值（副屏在主屏左侧/上方），但拒绝离谱坐标 |
| 非法输入不落盘 | 非数字、越界都会被拒，**不会覆盖**已保存的有效值 |

想恢复默认位置：删掉 `window.json`，或用 `--app-size` 显式指定尺寸。

> 普通浏览器标签页模式没有这个记忆（标签页大小由浏览器管理，页面量不准）。

### 方式二：一键启动（桌面快捷方式）

**首次使用**，创建桌面快捷方式（只需一次）：

```powershell
powershell -ExecutionPolicy Bypass -File install-shortcut.ps1
```

也可以右键 `install-shortcut.ps1` → **使用 PowerShell 运行**。加 `-StartMenu` 会同时建开始菜单项。

快捷方式默认就是**独立窗口模式**（带 `--app`）。想要普通浏览器标签页：

```powershell
powershell -ExecutionPolicy Bypass -File install-shortcut.ps1 -BrowserMode
```

之后双击桌面上的 **「OAS 账号列表管理」** 即可，不会弹黑色控制台窗口。

### 怎么退出

`pythonw` 启动没有窗口可关，用以下任一种（**推荐第 1 种**）：

| 方式 | 操作 |
| --- | --- |
| **页面按钮** | 点页面右下角 **「退出工具」**，确认后后端进程立即停止 |
| **关闭脚本** | 双击目录里的 `关闭账号管理.bat` |
| **命令行** | `python -B server.py --stop` |
| 任务管理器 | 结束 `pythonw.exe`（不推荐：会留下 `.runtime.json`，下次 `--stop` 会自动清掉） |

#### 关掉窗口后后台会怎样

**后台会一直跑着，直到你手动关**（这是刻意设计）：

- 关掉独立窗口**不会**停掉 `pythonw` 后端
- 再次双击启动**不会**新起进程 —— 检测到已在运行就直接复用、只开窗口，
  所以**反复开关也不会累积进程**
- 要彻底退出，用上面的「退出工具」/ `关闭账号管理.bat` / `--stop`

> 如果你希望"关窗口后自动退出"，可以加 `--idle-exit 60`（60 秒无心跳即退出）。
> 默认关闭，因为后台常驻更省事：下次打开秒开，不用等启动。

启动时会在工具目录写一份 `.runtime.json`（PID / 端口 / 启动时间），正常退出时自动删除。上面几种方式都读它来定位进程，所以**不用自己记端口**。重复双击启动也不会起第二个实例，会直接打开已有页面。

> 页面「退出工具」在**有未保存修改时会拒绝执行**，避免误关丢数据。

### 方式三：双击批处理

目录里有四个启动器，任选：

| 文件 | 特点 |
| --- | --- |
| `启动账号管理（独立窗口）.vbs` | **推荐**：完全静默 + 独立应用窗口（无地址栏/标签栏） |
| `启动账号管理（独立窗口）.bat` | 同上，但保留一瞬间的批处理窗口（排查问题用） |
| `启动账号管理.vbs` | 完全静默，但用普通浏览器标签页打开 |
| `启动账号管理（无窗口）.bat` | 用 `pythonw` 后台启动，普通标签页 |
| `启动账号管理.bat` | **保留控制台**，能看到日志、Ctrl+C 干净退出，排查问题用这个 |

重复双击不会起多个实例：检测到已在运行会直接打开页面并提示「工具已经在运行」。

### 方式四：命令行

在**仓库根目录**执行：

```powershell
# 独立窗口模式
python -B server.py --app

# 普通浏览器
python -B server.py
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--port 22299` | 监听端口（被占用会自动向后顺延） |
| `--host 127.0.0.1` | 监听地址，默认仅本机 |
| `--root <路径>` | OAS 仓库根（下面要有 `config/`）。**默认按 settings.json 的预设**，预设也没有时才逐级向上自动查找；也可直接指到 `config` 目录。支持局域网路径 `\\server\share` |
| `--app` | 用独立应用窗口打开（Chrome/Edge `--app` 模式，无地址栏/标签栏） |
| `--app-size 1280,860` | 独立窗口尺寸（**有 window.json 时以记住的为准**） |
| `--idle-exit 0` | 页面无心跳多少秒后自动退出。**默认 0 = 不自动退出**（后台常驻，手动关） |
| `--no-browser` | 不自动开浏览器 |
| `--selftest` | 跑离线自检后退出，不碰真实配置 |
| `--stop` | 停止正在运行的工具后退出（关掉 pythonw 起的实例） |

⚠ **运行中的 OAS 实例会覆盖你的修改**：脚本进程持有 `ConfigModel`，任何 `save()` 都会把内存里的旧账号表整体写回盘。**改之前请先在面板里停止该配置的实例**，改完再启动。

### 为什么不做成 exe

打包成独立 exe 需要 PyInstaller，代价是：

- 体积几十 MB，且每次改代码都要重新打包
- `server.py` 依赖同目录的 `ui.html` / `app.js` / `core.js` / `ui.css`，
  打包后要么内嵌（改页面也要重打包）要么外置（和现在没区别）
- 杀毒软件对无签名 exe 误报较多

现在的 `--app` 窗口模式已经能做到「双击 → 独立窗口、无地址栏」，且**改代码刷新即生效**，
维护成本低得多。真要 exe 时再单独打，不影响现有启动方式。

## 界面能做什么

| 操作 | 方式 |
| --- | --- |
| **自动排序** | 顶部「自动排序」按钮，按「排序方式」下拉执行 |
| **切换视图** | 「☰ 列表」（竖排，信息全）/「▦ 方块」（网格，紧凑）——选择会记住，下次打开还是上次的视图 |
| **每行几张卡** | 方块视图下可选「自动 / 2 / 3 / 4 / 6 / 8」。账号一般 4 个一组，**固定 4 列时一组正好占满一行**，不会像自动排列那样在宽窗口下排成 5 张把组拆开。选择会记住 |
| **拖拽调整** | 按住卡片左侧 `⠿` 拖动；落点会显示蓝线（卡片上半 = 插到它前面，下半 = 插到它后面） |
| **中间插队** | 鼠标移到两张卡片之间，出现「＋ 插入到第 N 位」 |

| **复制摘要** | 卡片右侧「⧉」——复制「区服-角色名-勾协类型」，如 `遥远之忆-银月二号-普勾` |
| **上移 / 下移** | 卡片右侧 ↑ ↓ |

### 勾协类型筛选的口径

「勾协类型」下拉只筛**本周期已确认**的结果：

| 选项 | 含义 |
| --- | --- |
| 全部 | 所有账号（含过期的、从未查找的） |
| 无勾 / 普勾 / 现勾 | **只算本周期查出来的**；上个周期查的（已过期）**不计入** |
| 勾协已过期 | 查过、但结果来自上个周期（本周期还没重查）——**不分类型** |
| 从未查找 | `jade_status` 还是 `none` 的 |

过期的不进任何类型，是因为"上个周期是普勾"不代表现在是 —— 现在可能变成现勾，
甚至已经不是勾协了。这和概览里「勾协已过期 N」单独统计是同一套口径：

- **类型筛选出来的数量 == 概览里 fresh 的数量**
- **「勾协已过期」的数量 == 概览里「勾协已过期 N」**

想看"哪些账号这个周期该重查但还没查"，直接选「勾协已过期」。

筛选结果为空、但确实有该类型的过期账号时，界面会补一句
"另有 N 个「普勾」是上个周期查的（已过期），本周期还没重查，不计入这里"，
并提示切到「勾协已过期」查看，避免误以为一个都没有。

### 批量导入：列顺序自动识别 + 共同值

直接从 Excel / 表格复制粘贴即可，**不用管列顺序**。工具按第一列判断是哪种格式：

| 第一列是 | 按这个顺序解释 | 例子 |
| --- | --- | --- |
| **平台**（iOS / 安卓 / 苹果…） | `平台, 账号, 服务器, 角色名[, 别名]` | `iOS  i154  雅乐之邦  紫星一号` |
| **其他**（账号） | `账号, 服务器, 角色名[, 别名][, 平台]` —— 与上一种**同顺序**，只省略平台 | `i154  雅乐之邦  紫星一号` |

所以你截图里这种表格可以直接整块复制进来：

```
iOS	i154	雅乐之邦	紫星一号
iOS	i154	花火之夏	紫星二号
iOS	i154	相伴相随	紫星三号
iOS	i154	砂狐乐园	紫星四号
```

#### 账号格里挂别名

账号格支持用逗号（中英文逗号、顿号都行）追加别名，**第一个是账号，其余都是别名**：

```
i154,小号1,小号2	雅乐之邦	紫星一号
```

解析结果：`account = i154`，`account_alias = 小号1#小号2`（OAS 的别名格式就是 `#` 分隔）。

> Tab 分列的行（Excel 复制的）里逗号专门用于挂别名，不会被误切成多列；
> 整行用逗号分隔的手工输入也支持（`i154,雅乐之邦,紫星一号`）。

#### 共同值开关

同一批账号的账号名 / 服务器 / 平台往往相同，勾选 **「使用共同值」** 后只需填一次，
行里留空就会自动补上。最省事的写法是**每行只写角色名**：

```
紫星一号
紫星二号
紫星三号
```

配合共同值 `账号=i154`、`系统=iOS`，就能得到完整的账号卡。

补值的优先级：**行内的格子 > 共同值 > 默认值（安卓 / 空）**。
也就是说某一行自己写了服务器，就用行内的，不会被共同值覆盖。

- 解析出的卡片数、跳过几行

| **放弃修改** | 底部「放弃修改」回到加载时的状态 |

### 导出 JSON（未脱敏）

顶部 **「导出 JSON」** 按钮打开弹窗，提供：

- **复制到剪贴板** —— 一键拿到完整 JSON
- **下载文件** —— 文件名形如 `桌面版1-assist_battle.json`

**与 OAS 自带导出的关键区别**：OAS 的「配置 → 导出任务」
（`/script/config/task/export`）会按 `CONFIG_REDACTION_PATHS` 脱敏，把
`assist_battle.account_list_*.account` / `account_alias` 替换成 `XXX`；
本工具**不脱敏**，账号原样保留。

```jsonc
// OAS 自带导出
"account_list_1": { "account": "XXX", "account_alias": "XXX", ... }

// 本工具导出
"account_list_1": { "account": "a1546296221@163.com", "account_alias": "", ... }
```

两个选项：

| 选项 | 内容 |
| --- | --- |
| **包含未保存的修改**（默认勾选） | 导出**当前页面上**的列表，包括还没保存的编辑 |
| 取消勾选 | 导出**磁盘上**的当前内容 |

> 导出**不会写盘**，只是读取后生成文本。

导出格式与 OAS 的「导出任务 / 导入任务」完全兼容（顶层是 `{ "assist_battle": {...} }`），
可以直接拿去导入。整份配置导出时顶层含 `config_name`，包含全部任务（约 68 个）。

⚠ 导出的 JSON **含完整账号信息**，转发或贴到公开地方时请注意。

### ⚠ 改了工具代码后必须重启

页面文件（`ui.html` / `app.js` / `core.js` / `ui.css`）每次请求都从磁盘重新读取，
所以**改完刷新浏览器就生效**；但 `server.py` 只在进程启动时加载。

如果你更新了工具却还在用旧进程，新接口会返回 404，页面顶部现在会显示红色提示条：

> ⚠ 后端服务是旧版本，部分功能（如导出 JSON）不可用
> 页面已经是新代码，但 server.py 的修改要重启进程才生效。

**重启方法**：点页面右下角「退出工具」，再双击桌面快捷方式（或 `启动账号管理.bat`）。

工具用 `CONTRACT_VERSION`（前后端各一份，需一致）来检测这种不一致，
`check-version.js` 会校验两边版本号是否同步 —— 加新接口时记得同时递增两处。

### 两种排序方式

顶部「排序方式」下拉，默认是 **账号 → 系统 → 编号**。

### 三级排序（两种方式共享前两级）

```
第 1 级：账号      自然序，a2 在 a10 前
第 2 级：系统      「系统优先」控制：安卓在前 / iOS 在前
第 3 级：编号 或 角色名   ← 两种排序方式唯一的区别
```

**关键：编号是第三级，不会越过系统。** 同一个账号下，安卓的六号会排在 iOS 的二号之前（因为系统优先），而不是按编号把二号提到最前。

**① 账号 → 系统 → 编号（默认，推荐）**

第三级按角色名里抽出的编号比大小，专为「汉字数字 + 号」的命名准备：

```
a 账号：银月六号(6) → 银月七号(7) → 银月八号(8) → 银星二号(2, iOS)
b 账号：红月五号(5) → 红月六号(6) → 红月七号(7) → 红月八号(8)
```

> 注意上面 a 账号里的 `银星二号` 排在安卓的三张卡之后 —— 这是**故意的**：它是 iOS 号，系统优先于编号。把「系统优先」切到「iOS 在前」，它就会排到 a 账号最前面。

支持三种编号写法（抽不到编号的卡排在同账号同系统最后）：

| 写法 | 例子 | 编号 |
| --- | --- | --- |
| 汉字数字 + 单位 | `银月六号`、`十五号`、`二十三号`、`一百零五号` | 6 / 15 / 23 / 105 |
| 阿拉伯数字 | `银月6号`、`acct-06` | 6 |
| 纯汉字数字 | `银月六` | 6 |

> 为什么需要编号：中文拼音序是 `八(bā) < 六(liù) < 七(qī) < 五(wǔ)`，直接按名字排会得到 `八号 → 六号 → 七号 → 五号` 这种乱序。按编号才能得到 `二号 → 五号 → 六号 → 八号`。
>
> 多段数字时取**最后一段**（`十区银月六号` → 6），符合「前缀 + 编号 + 单位」的常见写法。

**② 账号 → 系统 → 角色名**

第三级直接按角色名拼音。适合角色名里没有编号、或者编号不连续的情况。

### 运行状态（今天跑没跑一眼看出来）

每张卡片都显示 **上次执行时间** 和 **运行状态**，三种状态用「左侧色条 + 标签 + 底色」三重区分：

| 状态 | 卡片外观 | 标签 | 时间显示 |
| --- | --- | --- | --- |
| **今天已执行** | 绿色左条 + 淡绿底 | `✓ 今天已执行` | `今天 08:15` |
| **今天未执行** | 橙色左条 + 淡黄底 | `今天未执行` | `昨天 23:05` / `3 天前 20:00` / `10-1 09:00` |
| **从未执行** | 灰色左条 + 灰底 | `从未执行` | `从未执行` |

顶部还有 **「运行状态」筛选**，可以直接只看「今天未执行」的账号：

```
全部 / 今天已执行 / 今天未执行 / 从未执行
```

筛选**只影响显示**，不会改动列表顺序或内容 —— 卡片序号仍是它在配置里的真实位置。

概览栏也会统计 `今天已执行 N / 今天未执行 N / 从未执行 N`。

#### 数据来源与判定规则

用的是 `last_complete_time` 字段，它由协战脚本在账号完成当天协战后写入 `datetime.now()`，
`AssistBattle.is_account_done_today()` 就是拿它的 `.date()` 和今天比对，决定是否跳过该账号。

判定逻辑（与脚本一致）：

- 时间落在**今天** → `今天已执行`
- 落在**昨天或更早** → `今天未执行`（显示相对天数，超过一周只显示日期）
- 以下都算**从未执行**：
  - 空值 / 无法解析
  - `2023-01-01 00:00:00`（`AccountInfo` 字段默认值）
  - `1970-05-11 07:36:15` —— 这个值 = **`0xABCDEF` 秒**，是 OAS 里「该字段不参与」的哨兵值

编辑卡片时可以直接用两个快捷按钮：

- **标记今天已执行** → 填入当前时间
- **标记从未执行** → 重置为默认值

> ⚠ 手工把时间改成今天，会让该账号**今天被跳过**（当 `skip_completed_account_enable` 开启时）。
> 反过来，把「今天未执行」的账号时间清掉不会有副作用，只是丢了历史记录。

列表上还会提示：

- `空角色` / `不会执行`：角色名为空，OAS 的 `is_valid()` 要求 `character` 非空，这种卡不会被执行
- `重复账号+角色`：同一账号下的同名角色（多半是误导入）

## 安全措施

1. **写前备份**：每次保存前把原文件复制到 `backups/{配置}.{时间戳}.json`
2. **原子写入**：临时文件 + `os.replace`，中途失败不会留下半个文件
3. **并发冲突保护**：加载时记录文件 mtime，保存时若文件已被改动（典型情况：OAS 实例回写了配置）会**拒绝保存**并提示重新加载
4. **只动目标列表**：只重写该任务的 `*_list_N` 和对应计数字段，其它任务/字段原样保留
5. **路径防护**：配置名不允许 `/` `\` `..`
6. **空列表兜底**：模型约束是 `ge=1`，列表清空时 `account_count` 写 1
7. **读取容错**：别的进程正在写配置时会读到半截 JSON，`_read_json` 会短暂重试
   （6 次 × 50ms）再报错，不把"正在被写"误报成"配置坏了"
8. **失败不清空界面**：读取失败时保留当前列表并提示重试，不会把卡片清空
9. **计数分组改名兼容**：OAS 的 `account_count` 所在分组改过两次名
   （`assist_battle_config` → `battle_config` → 又改回来）。
   工具不写死名字，而是 `resolve_count_group()` **优先用配置里实际存在的那个**，
   都没有才新建。写死在改名后会新建空节点、真实计数永远不同步
   （表现就是"加/删账号但数量不变"）

### 「重新加载」为什么不刷新（2026-10-31 修复）

用户反馈"点重新加载有时候不会刷新，需要连点几下"。实测确认是三个独立原因叠加：

| 原因 | 机制 | 修复 |
| --- | --- | --- |
| 前端无并发守卫 | 连点时多个 `/api/list` 同时在飞，先发的响应可能后到，把新数据覆盖成旧数据 | `loadSeq` 只认最后一次请求，过期响应直接丢弃 |
| 读取失败清空列表 | OAS 式非原子写让读取撞上半截 JSON，旧代码把列表清空，看起来像"没刷新" | 失败时保留旧数据 + 提示"再点一次" |
| 连接排队太小 | HTTP/1.0 每请求新建连接，默认 `request_queue_size=5`，并发 8 时约 1/9 被内核丢弃（fetch failed） | `_AccountServer.request_queue_size = 128` |

复现数据（修复前 → 修复后）：
- 并发 8 个请求的失败数：4/64 → 0/64；并发 24：88/192 → 0/192
- 非原子写进行中连点 40 次：读取失败 11/40 → 0/40
- 注入乱序响应后连点 3 下：界面停在第一次的数据 → 正确显示最后一次

> 后端的两项修复要**重启进程**才生效，所以 `CONTRACT_VERSION` 从 5 升到 6，
> 旧进程的页面会显示"后端是旧版本，请重启"的提示条。

## 自检

**一条命令跑完全部检查**（推荐）：

node check-dom.js

node check-theme.js

# 按钮不溢出：卡片网格列数够不够、按钮有没有裁剪文字
node check-button-fit.js

# 每行卡片数：固定 4/8 列 + 记忆 + 白名单校验
node check-grid-cols.js

node check-overflow.js

node check-sort-ui.js

# 版本契约：页面与后端进程版本是否一致（不需要服务）
node check-version.js

# 重新加载可靠性：并发守卫 / 失败保留旧数据 / 连接排队上限

node check-portable.js

## 已知限制

- **排序只在前端做**。后端不重复实现中文排序，避免两套规则不一致；因此通过 API 直接写卡片时，顺序就是调用方给的顺序。
- **不校验 `svr`/`character` 的真实性**。切号时是按角色名和服务器去游戏里找，填错了只会在运行时切号失败。
- **`last_complete_time` 会跟着卡片走**，排序/插入不会打乱"今天已完成"的判断（已实测）。
- 若要长期解决"面板内直接增删排序"，正解仍是给 OAS 加一个"整表读写"接口 + OASX 换成可拖拽列表；本工具是那之前的过渡方案，也能继续当批量导入/离线整理用。
